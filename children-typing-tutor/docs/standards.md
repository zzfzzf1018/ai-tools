# 开发与评审规范

## 基本约定

- TypeScript 严格模式；不使用 `any` 或忽略类型诊断绕过错误。
- React 组件只组织交互，计分、解锁和存储校验放在可独立测试的模块。
- 命名描述业务含义；避免不必要的抽象、全局事件拦截和渲染过程副作用。
- UTF-8、LF、两空格缩进；Prettier 统一格式，ESLint 检查代码。中文教学和文档必须保持可读，不转义成 Unicode 序列。
- 共用课程和素材；不要为网页和桌面复制两套判定逻辑。
- 本地插画、字体和声音必须可离线运行；引入外部素材前核对许可证并补充来源。
- 不提交依赖目录、构建产物、测试追踪、个人记录、下载缓存、代理凭据或签名证书。锁文件必须保留。
- 不未经请求创建分支、提交代码、添加商业签名或部署外网。

## 修改流程

1. 从具体行为和负责模块定位，写出可被测试否定的假设。
2. 进行最小变更；第一次实质修改后立即运行对应单测或类型检查。
3. 失败时先修复同一范围并重跑，不把失败藏在更大改动里。
4. 完成一批功能后自查输入边界、状态生命周期、持久化、离线和平台差异。
5. 每项有效发现都应修复并增加合适回归；再次检查直到没有已知阻断问题。
6. 需求、设计、命令或约束变化时同步文档；测试不能执行时记录原因，不能宣称通过。

## 课程内容规范

新增课程需提供唯一顺序 ID、所属章节、新字符集、中文讲解、手指提示、跟练和小测。所有字符必须在当前或更早课程中明确教授；通过内容单测验证。键位按 US QWERTY，B 使用左食指，Shift 尽量用对侧手。

鼓励准确、放松和重试，不用羞辱、扣生命或强制竞争。更改 85% 门槛、计分公式或课程先修属于需求变更，先更新需求文档和边界测试。

## 评审清单

- 正确/错误/退格/长按/输入法/快捷键是否一致？
- 是否只在练习区拥有焦点时拦截按键？暂停、窗口失焦、切后台是否排除时间？
- 定时练习是否在截止后停止接收，结果与奖励是否只保存一次？
- 未完成导航有确认，完成后导航不应假称有未保存输入；弹窗能否键盘进入/退出？
- 损坏、缺字段、负数、无权限和配额不足是否安全降级？
- 游戏是否只使用允许的按键？新增文案是否带入未教授字符？
- 网页离线状态是否有真实缓存证据？是否实际断网刷新而非只断言 Worker 存在？
- 桌面是否启动真实打包 exe？资源是否本地加载？安全隔离是否未被放宽？
- 多尺寸是否有溢出、截字、重叠、不可见目标字符或缺图？
- 是否同步文档和忽略规则，是否有未声明的交付限制？

## 发布门禁

1.1 增量检查要求：

- 版本 1 原记录迁移后，课程、设置与累计字段不丢失，不伪造按键统计；旧键保留，新键优先，明确重置时清理旧键。
- 统计仅在完成且去重后保存；退格不抹历史、跟练不领奖，专项复习不能使用未通过课程的字符或解锁课程。
- 导出 JSON 可恢复且不含附加隐私字段；导入必须预览和确认，大小限制、未知版本、非法值、存储拒绝与异步关闭都需回归。
- 两种实际 Windows exe 都须验证新统计、专项、真实备份文件和恢复后的重启持久化；四种尺寸检查新视图与备份预览。

```powershell
npm run typecheck
npm run lint
npm test
npm run format:check
npm run test:e2e
npm run desktop:package
$env:DESKTOP_EXECUTABLE = (Resolve-Path 'release/win-unpacked/Typing Island.exe').Path
npm run test:desktop
Remove-Item Env:DESKTOP_EXECUTABLE
npm audit --omit=dev
```

发布记录必须给出执行环境、实际通过的检查、审查发现及修复、产物名称和剩余限制。出现未解决的严重/高风险问题或主流程失败不得封板。安装包签名、目标系统覆盖不足等非本期事项需显式披露；“封板”不是永无缺陷的保证。
