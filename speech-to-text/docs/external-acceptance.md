# 正式封板的外部验收

工程验收与业务验收分开记录。随完整集成包提供的 `validation/release-evidence.json` 是本轮工程测试证据。
其 `formal_release_status` 记录自动构建时状态，不能仅因自动化全绿而声称干净机器和业务录音已经通过。
2026-10-31 用户已确认人工验收成功并授权 v1.0.1 封板发布，见 [人工确认](manual-acceptance.json)。确认不等于补造独立干净机器回执或量化准确率。

## 未安装 Python 的 Windows 电脑

1. 使用 Windows 10/11 x64 普通用户账户，拿到本轮完整集成构建的 ZIP，核对同名 SHA-256 校验文件。
2. 完整解压，进入 SpeechToText 文件夹，确认有 `acceptance.cmd`、`validation/clean_windows.ps1` 和测试媒体。
3. 双击 `acceptance.cmd`。它不安装 Python，会先检查已有 Python；如果检测到，则本机不作为干净机器证据。
4. 脚本验证 EXE 原生诊断，下载 small 模型到新的独立缓存，再在离线模式执行中英文 MP3/MP4/MKV、延迟音轨和静音测试。
5. 结果写到桌面 `SpeechToText-Acceptance/clean-windows-result.json`，错误日志和输出也保留在该目录。
6. 再双击 EXE，人工确认界面、添加文件、开始转写、打开输出和帮助入口可用；将操作结果、JSON 和窗口截图交给维护人员。

首次需要联网下载数百 MB 模型，缓存保留在本机用户目录，不上传音视频。
成功仅证明检测未安装 Python 的电脑上的应用诊断、首次模型下载及离线合成样本流程通过；
不是业务准确率证明，也不宣称操作系统从未安装过其他开发工具。结果含机器名和本地路径，分享前检查隐私。

没有另一台电脑时，保持待验收。不卸载本机 Python、不修改系统虚拟化功能，更不将 PATH 隔离当作干净操作系统。

## 真实业务音视频

由使用者提供脱敏样本和独立标准答案，覆盖中文、英文和 MP3、MP4、MKV；
中英混合、多人重叠、噪音或特殊音轨业务应补充对应代表性样本。

1. 测试前明确中文字符错误率 CER、英文词错误率 WER、字幕起止偏差允许值及处理耗时和内存约束。
2. 标准文字和字幕必须由原录音独立校对，不能把本工具输出直接当作标准答案。
3. 用本轮 EXE、small、CPU/int8 处理样本，保存 TXT/SRT/VTT、输入校验值、参数和日志。
4. 对照标准统计替换、删除、插入和 CER/WER；在播放器抽检首句、末句、静音后、音轨延迟后及中间关键语句。
5. 未达到标准时记录具体文件和时间位置，修复后按同一标准重新验收，不调整阈值凑通过。
6. 保存验收人、日期、EXE SHA-256、源码指纹、每个样本结果和明确签字结论。

本次已在代码库外执行用户真实视频测试并收到人工验收确认；未提供独立标准全文和量化阈值，不填写虚构错误率，不把真实视频或结果提交入库。
