# 测试与发布

本文说明测试体系、产物校验、CI 工作流与发布流程。

---

## 1. 测试分层

```
┌─────────────────────────────────────────────┐
│  产物校验  scripts/verify.mjs                │  jsdom 真实加载单文件版
├─────────────────────────────────────────────┤
│  界面集成  tests/ui.test.js                  │  jsdom + 真实事件
├─────────────────────────────────────────────┤
│  数据校验  tests/data.test.js                │  词库完整性
├─────────────────────────────────────────────┤
│  单元测试  tests/{srs,store,scheduler,       │  纯函数，无 DOM
│            quiz,stats,session}.test.js       │
└─────────────────────────────────────────────┘
```

运行：

```bash
npm test          # 单元 + 集成 + 数据（102 个用例）
npm run verify    # 以上全部 + 构建 + 产物校验
npm run test:e2e  # 真实浏览器端到端（需先 npm run build）
```

### 2.8 `ui.test.js` — 界面集成（14 例）

用 jsdom 构建真实 DOM 并调用 `createApp()`，通过派发 `MouseEvent` / `Event` 模拟交互：

挂载渲染、导航切换、开始学习、作答翻面、评分推进、词库分页与标记、标记掌握、搜索过滤、空态、设置持久化、主题切换、学习页标记掌握、结束本轮展示结果页。

关键点：

- 每次用例重建 JSDOM 实例并清空 localStorage，用例间完全隔离
- 不使用 `global.navigator`（Node 22 中是只读 getter），只注入 `window` / `document`
- `speechSynthesis` 在 jsdom 中不存在，`canSpeak()` 会安全返回 false

### 2.9 `scripts/verify.mjs` — 产物校验（7 项）

| 检查 | 内容 |
| --- | --- |
| 单文件版存在 | 体积在 400 KB – 3 MB 之间 |
| 内联词库数据 | 解析 `window.__WORD_DATA__`，确认 8000 条 |
| 无外部依赖 | 无外部 `<script src>`、无 `<link rel=stylesheet>`、无 http(s) 资源 |
| 脚本样式内联 | 含 `<style>`、`<script>`、应用标识 |
| **可独立启动** | jsdom `runScripts: dangerously` 加载并等待挂载，再点进词库确认渲染 50 行 |
| Web 版完整性 | index.html 引用正确、不内联数据、assets 与 data 存在 |
| 版本一致 | version.json 与 package.json 版本号、词数、指纹格式 |

### 2.10 `scripts/e2e.mjs` — 浏览器端到端（18 项）

用 playwright-core 驱动系统 Chrome/Edge，在真实浏览器中走一遍完整用户路径：

学 8 张卡 → 等待落盘 → 刷新验证持久化 → 标记掌握 → 标记重点 → 搜索 → 修改设置 → 导出备份 → 清空进度 → 导入恢复 → 空格翻面 → 数字键评分 → 切换主题 → 检查控制台无报错。

脚本会自动启动预览服务器、跑完关闭，一条命令完成。可通过 `CHROME_PATH` 指定浏览器，`E2E_PORT` 指定端口。

这一层与 jsdom 测试互补：jsdom 验证逻辑与 DOM 结构，真实浏览器验证 localStorage 写入、文件下载、CSS 渲染与键盘事件。

「可独立启动」这一项曾捕获过一个真实 bug：构建脚本用 `String.replace` 注入 JS 时，压缩产物里的 `$&` 被当作替换模式，导致单文件版脚本损坏。详见 `docs/技术架构.md` 第 7 节。

## 4. CI 工作流

### 4.1 `.github/workflows/word-memory-ci.yml`

触发：PR 或 push 到 main，且改动涉及 `word-memory/**` 或本工作流自身。

步骤：

1. `actions/checkout`
2. `actions/setup-node`（Node 22，启用 npm 缓存）
3. `npm ci`
4. 语法检查：对 `src/**/*.js` 与 `scripts/*.mjs` 执行 `node --check`
5. `npm test`
6. `npm run build`
7. `node scripts/verify.mjs`
8. 上传单文件版为构建产物（保留 7 天）

超时 15 分钟，并发组按分支取消旧任务。

### 4.2 `.github/workflows/word-memory-release.yml`

触发：推送 `word-memory-v*` tag，或手动指定 tag 重新发布。

权限：`contents: write`（创建 Release）、`pages: write` + `id-token: write`（部署 Pages）。

任务：

**build**（ubuntu-latest）

1. 检出代码、安装依赖
2. `npm test` → `npm run build` → `npm run verify`
3. 把 `dist/word-memory.html` 重命名为 `word-memory-<version>.html`
4. 生成发布说明（`scripts/release-notes.mjs` 从 CHANGELOG 提取）
5. 上传两个 artifact：`single-file`、`web-dist`

**release**（needs build）

1. 下载 `single-file` artifact
2. `gh release create` 创建 Release，标题 `WordMemory v<version>`，附上单文件版与发布说明

**pages**（needs build）

1. 下载 `web-dist` artifact
2. `actions/configure-pages` → `actions/upload-pages-artifact` → `actions/deploy-pages`
3. 输出部署地址

## 5. 发布流程

```bash
# 1. 确认基线
cd word-memory
npm install
npm run verify          # 必须全部通过

# 2. 更新版本号
npm version 1.0.1 --no-git-tag-version

# 3. 更新 CHANGELOG.md（新增 ## [1.0.1] - YYYY-MM-DD 段落）

# 4. 提交
git add word-memory
git commit -m "chore(word-memory): 发布 1.0.1"

# 5. 打 tag 并推送
git tag word-memory-v1.0.1
git push origin main --tags
```

推送 tag 后，Actions 会自动构建、创建 Release 并部署 Pages。

### 版本号约定

| 变更类型 | 版本位 | 例子 |
| --- | --- | --- |
| 破坏性改动（数据结构不兼容） | major | 2.0.0 |
| 新功能（如新增题型） | minor | 1.1.0 |
| 修复与优化（不影响数据） | patch | 1.0.1 |

### 词库更新

如果重新生成了 `data/words.json`（换了词表或改了清洗规则）但没有改动顺序，属于 patch；如果顺序发生变化（用户记录会错位），属于 major，且必须在发布说明中显著提示用户先导出备份。

## 6. 本地排查

**测试失败但看不出原因**

```bash
node --test tests/srs.test.js           # 单文件跑
node --test --test-reporter=spec tests/ # 详细输出
```

**产物校验失败**

```bash
npm run build && node scripts/verify.mjs
```

若「可独立启动」失败，先在浏览器打开 `dist/word-memory.html` 看控制台报错，通常是构建时字符串注入或数据格式问题。

**jsdom 相关报错**

- `Cannot set property navigator of #<Object>` → 不要注入 `global.navigator`
- `localStorage is not available` → JSDOM 需要设置 `url` 选项（非 `about:blank`）

**CI 上 npm ci 失败**

确认 `package-lock.json` 已提交，且与 `package.json` 同步（本地执行一次 `npm install` 后提交 lock 文件）。
