# 技术架构

本文说明项目的分层、数据流、渲染策略与构建管线，供二次开发参考。

---

## 1. 设计原则

| 原则 | 具体做法 |
| --- | --- |
| **运行时零依赖** | 不用 React/Vue，不改动构建产物以外的任何运行时库。单文件版因此可以做到 646 KB |
| **逻辑与视图分离** | `src/core` 不引用任何 DOM API，可在 Node 中直接 import 测试 |
| **单一数据源** | 所有状态都在 `store` 中，视图是状态的纯函数映射 |
| **一份模板，两个产物** | `src/index.html` 通过三个占位符分别注入外链资源或内联资源 |
| **数据可复现** | 词库管道不含时间戳等易变字段，同样输入必得同样输出 |

## 2. 分层

```
┌──────────────────────────────────────────────┐
│  src/main.js          入口：加载数据 → 启动   │
├──────────────────────────────────────────────┤
│  src/ui/app.js        控制器：路由/状态/事件  │
│    ├─ views/*.js      纯字符串渲染函数        │
│    ├─ dom.js          DOM 辅助 / 语音 / 弹层  │
│    └─ icons.js        内联 SVG                │
├──────────────────────────────────────────────┤
│  src/core/*          纯逻辑（无 DOM）         │
│    srs · session · scheduler · quiz           │
│    store · wordbook · stats · util            │
├──────────────────────────────────────────────┤
│  data/words.json      8000 词数据集           │
└──────────────────────────────────────────────┘
```

依赖方向严格单向：`ui → core → 数据`，`core` 不反向依赖 `ui`。

## 3. 数据流

```
                  ┌──────────────┐
                  │ words.json   │
                  └──────┬───────┘
                         │ createWordbook()
                         ▼
┌────────────┐    ┌──────────────┐    ┌──────────────┐
│ localStorage│◄──►│    store     │◄──►│   session    │
└────────────┘    └──────┬───────┘    └──────┬───────┘
                         │                   │
                         ▼                   ▼
                  ┌──────────────────────────────┐
                  │        buildCtx()            │
                  │  聚合：overview + settings    │
                  │        + session 状态         │
                  └──────────────┬───────────────┘
                                 ▼
                  ┌──────────────────────────────┐
                  │   VIEWS[state.view](ctx)     │
                  │   → HTML 字符串 → innerHTML  │
                  └──────────────┬───────────────┘
                                 ▼
                  ┌──────────────────────────────┐
                  │  事件委托 → actions → 改状态  │
                  └──────────────────────────────┘
```

一次点击的完整链路（以「评分」为例）：

1. 按钮带 `data-action="grade" data-grade="2"`
2. 根节点上的委托监听器匹配到 `[data-action]`
3. 调用 `actions.grade(el)` → `submitGrade(2)`
4. `session.submit(2)` → `store.recordReview()` → `srs.review()` 算出新状态
5. `store.bumpDaily()` 累加当日统计
6. `loadCard()` 为下一张卡生成题目
7. `render()` 重新渲染整个视图

## 4. 状态管理

应用状态集中在 `createApp()` 闭包内的 `state` 对象：

```js
state = {
  view: 'today',          // 当前视图
  session: null,          // 学习会话对象（含队列）
  question: null,         // 当前题目
  phase: 'quiz',          // 'quiz' | 'reveal'
  picked: '',             // 用户作答
  feedback: null,         // 'correct' | 'wrong'
  browse: { query, filter, level, page, pageSize },
}
```

持久状态（跨会话）在 `store` 中，两者职责清晰：

- `state` 是**会话级**的，刷新即丢（除了 view 通过 URL hash 保留）
- `store` 是**持久化**的，写入 localStorage

## 5. 渲染策略

### 5.1 全量重渲染 + 焦点恢复

每次状态变化都重新生成整个视图的 HTML 并赋给 `innerHTML`。

优点是简单、不会有「局部更新漏掉某处」的 bug；代价是丢失 DOM 状态（焦点、光标位置、滚动位置）。

补偿措施：

```js
const scroll = mainEl.scrollTop;
const activeId = document.activeElement?.id;
const selection = document.activeElement?.selectionStart;

viewRoot.innerHTML = VIEWS[state.view](ctx);

mainEl.scrollTop = scroll;
if (activeId) {
  const el = document.getElementById(activeId);
  el.focus();
  el.setSelectionRange(selection, selection);
}
```

这样在搜索框里连续打字时，每次输入触发重渲染后光标仍然在原位。

### 5.2 事件委托

只在 `root` 上绑定一次 `click` 监听，通过 `event.target.closest('[data-action]')` 找到触发元素：

```js
delegate(root, 'click', '[data-action]', (event, el) => {
  actions[el.dataset.action]?.(el);
});
```

这样重渲染不会丢事件，也不需要每次渲染后重新绑定。

### 5.3 局部更新的例外

两处例外，因为它们不需要重建 DOM：

- `[data-setting]` 输入框：只更新 store，不重渲染（避免打断输入）
- `#spell-input`：只同步 `state.picked`，不重渲染

多页列表（词库 8000 词）用分页而非虚拟滚动：每页 50 行，渲染成本约 3–5 ms，滚动体验完全可接受，代码量却少了一个数量级。

## 6. 存储层

### 6.1 适配器模式

```js
createStore({ adapter })
```

`adapter` 只需实现 `get / set / remove`。内置两种：

| 适配器 | 用途 |
| --- | --- |
| `createLocalAdapter(localStorage)` | 浏览器持久化 |
| `createMemoryAdapter()` | Node 测试、隐私模式降级 |

启动时先探测 localStorage 是否可写：

```js
try {
  storage.setItem(probe, '1');
  storage.removeItem(probe);
  return createLocalAdapter(storage);
} catch {
  return createMemoryAdapter();   // 降级
}
```

降级后界面仍可正常使用，只是明确提示「无法自动保存进度，请导出备份」。

### 6.2 自动保存

写入不是每次操作都落盘，而是标记 dirty 后用 400 ms 防抖合并：

```
操作 → markDirty() → 重置定时器
                     ↓ 400ms 无操作
                   save()
```

另外在 `visibilitychange → hidden` 和 `beforeunload` 时强制 `flush()`，避免切走页面丢数据。

### 6.3 只存变化

默认状态（`s=0, star=0, seen=0, lapse=0`）不写入存储。首次打开应用时 `words` 是空对象，占用几乎为 0。只有在用户真正开始学习后才逐条增加。

8000 词全部学完时约占用 700–900 KB，远低于 localStorage 的 5 MB 限制。

## 7. 构建管线

```
src/main.js ──esbuild(bundle,minify,iife)──► dist/web/assets/app.js
src/styles/main.css ──esbuild(minify)─────► dist/web/assets/app.css
src/index.html ──替换占位符───────────────► dist/web/index.html
data/words.json ─────────────────────────► dist/web/data/words.json
                        │
                        └──内联──► dist/word-memory.html（单文件）
```

模板中的三个占位符：

| 占位符 | Web 版替换为 | 单文件版替换为 |
| --- | --- | --- |
| `<!--APP_CSS-->` | `<link rel="stylesheet" href="assets/app.css">` | `<style>…</style>` |
| `<!--APP_DATA-->` | 空 | `<script>window.__WORD_DATA__=…</script>` |
| `<!--APP_JS-->` | `<script src="assets/app.js"></script>` | `<script>…</script>` |

### 踩过的坑：`String.replace` 的 `$` 语义

最初写成：

```js
template.replace('<!--APP_JS-->', `<script>${js}</script>`)
```

结果单文件版一打开就报 `Unexpected token '<'`。

原因：压缩后的 JS 里含有 `$&`（esbuild 把变量名压成了 `$`，出现了 `$&K(...)` 这样的代码）。而 `String.prototype.replace` 的**替换字符串**里，`$&` 表示「匹配到的子串」，于是 `<!--APP_JS-->` 被原样插回了脚本中间。

修复：所有替换改用函数形式，返回值不再被解析为替换模式。

```js
template.replace('<!--APP_JS-->', () => `<script>${js}</script>`)
```

`scripts/verify.mjs` 里的「单文件版可独立启动」用例，就是用 jsdom 真实执行产物来防这类问题的回归。

### 内联安全处理

```js
function safeInline(text) {
  return text.replace(/<\/script/gi, '<\\/script').replace(/<\/style/gi, '<\\/style');
}
```

防止字符串里意外出现的 `</script>` 提前闭合标签。

## 8. 双版本一致性

两个版本跑的是**同一份 JS、同一份 CSS、同一份数据**，唯一差别是资源加载方式：

- Web 版：`fetch('data/words.json')`
- 单文件版：读取 `window.__WORD_DATA__`

`src/main.js` 里的分支：

```js
async function loadPayload() {
  if (window.__WORD_DATA__) return window.__WORD_DATA__;
  const res = await fetch(new URL('data/words.json', document.baseURI));
  return res.json();
}
```

这意味着任何功能改动只需验证一次逻辑，不会出现「网页版能用、单文件版不行」的分裂。

### 为什么单文件版必须用普通 `<script>`

`file://` 协议下浏览器的模块加载受 CORS 限制，`<script type="module">` 会被拒绝执行。所以 esbuild 输出格式选择 **IIFE** 而非 ESM，单文件版直接内联为普通脚本即可。

## 9. 性能

| 场景 | 耗时 | 说明 |
| --- | --- | --- |
| 词库加载与索引 | ~30 ms | 8000 条转小写 + 分频段桶 |
| 首屏渲染 | ~15 ms | 今日页 |
| 词库列表渲染 | ~5 ms | 每页 50 行 |
| 全库搜索 | ~2 ms | 8000 条线性扫描 |
| 队列构建 | ~4 ms | 遍历 8000 条 + 排序 |
| 统计计算 | ~3 ms | 遍历一次聚合 |

这些都是毫秒级，所以没有做缓存、虚拟列表等优化——保持代码可读性更重要。

唯一需要留意的是 `getState()` 返回副本（浅拷贝 11 个字段），在 8000 次循环里会产生 8000 个小对象。实测影响在 2 ms 以内，可接受。

## 10. 扩展点

想加功能时，改动位置如下：

| 需求 | 改哪里 |
| --- | --- |
| 新增题型（如听音辨词） | `core/quiz.js` 的 `buildQuestion` + `ui/views/study.js` 的渲染分支 |
| 调整算法参数 | `core/srs.js` 顶部常量 |
| 新增学习模式（如只复习） | `core/scheduler.js` 的 `buildQueue` |
| 新增统计维度 | `core/stats.js` + `ui/views/stats.js` |
| 新增页面 | `ui/views/` 加文件 + `app.js` 的 `NAV` / `VIEWS` |
| 换词库 | 改 `scripts/build-data.mjs` 的源地址与清洗规则，保持输出格式 `[word, meaning, phonetic, level]` |
| 云端同步 | 实现一个新的存储 adapter（保持 `get/set/remove` 接口），替换 `resolveAdapter()` |
