# 数据结构

本文说明三层数据格式：词库数据、本地存储、导出备份。

---

## 1. 词库数据 `data/words.json`

由 `scripts/build-data.mjs` 生成，是构建产物而非手写文件。

### 1.1 顶层结构

```json
{
  "meta": {
    "name": "WordMemory 8000 核心词库",
    "version": "1.0.0",
    "count": 8000,
    "source": "COCA 20000 frequency list (via qwerty-learner)",
    "sourceUrl": "https://cdn.jsdelivr.net/gh/Kaiyiwing/qwerty-learner@master/public/dicts/coca20000.json",
    "sourceHash": "4afd6304292568dc",
    "sourceCount": 20199,
    "levels": {
      "1": { "name": "核心", "range": "1-1000",   "count": 1000 },
      "2": { "name": "常用", "range": "1001-3000", "count": 2000 },
      "3": { "name": "进阶", "range": "3001-5500", "count": 2500 },
      "4": { "name": "拓展", "range": "5501-8000", "count": 2500 }
    },
    "fields": ["word", "meaning", "phonetic", "level"]
  },
  "words": [
    ["the",  "art. 指已提到的人（物）；指说话人与听者已知的人（物）", "ðə", 1],
    ["be",   "v. 是；有 aux. 用来表示某人或某物即主语本身…",        "bi", 1],
    ["and",  "conj. 和；与",                                        "ənd", 1]
  ]
}
```

### 1.2 为什么用数组而不是对象

每个词用 `[word, meaning, phonetic, level]` 四元组，而不是 `{word, meaning, phonetic, level}` 对象。

对比：

| 方案 | 单条开销 | 8000 条总计 |
| --- | --- | --- |
| 对象 | `{"word":"the","meaning":"…","phonetic":"ðə","level":1}` | ~1.35 MB |
| 数组 | `["the","…","ðə",1]` | ~0.55 MB |

省下约 60% 体积，代价是字段位置需要约定。由于字段顺序固定且由 `meta.fields` 显式声明，这个代价可以接受。

数组下标与字段的对应关系只在 `core/wordbook.js` 的 `wordAt()` 中处理，其他模块一律使用具名对象：

```js
function wordAt(index) {
  const row = words[index];
  return {
    index,
    word: row[0],
    meaning: row[1] || '',
    phonetic: row[2] || '',
    level: row[3] || 1,
  };
}
```

### 1.3 字段约束

| 字段 | 类型 | 约束 | 校验用例 |
| --- | --- | --- | --- |
| `word` | string | `^[A-Za-z][A-Za-z'-]*$`，长度 1–32，全库唯一（忽略大小写） | `data.test.js` |
| `meaning` | string | 非空，长度 ≤ 60，不含 U+FFFD，不为「无」 | `data.test.js` |
| `phonetic` | string | 可为空（约 0.3% 无音标），不含中文 | `data.test.js` |
| `level` | number | 1 / 2 / 3 / 4 | `data.test.js` |

### 1.4 索引即词频排名

`words` 数组的顺序就是词频排名：

- `words[0]` 是 `the`（COCA 排名第 1）
- `words[7999]` 是第 8000 个高频词

这个顺序被用在三个地方：

1. 新词默认按这个顺序出现
2. 词库列表的序号显示
3. localStorage 里以索引作为键

**因此，重新生成词库时必须保持顺序稳定**，否则用户已有的学习记录会错位。`meta.sourceHash` 用于检测这种情况。

### 1.5 数据管道

```
coca20000.json（20199 条）
        │
        ├─ 去重（忽略大小写）                    剔除 ~1250
        ├─ 剔除首字母大写的专有名词（保留白名单）  剔除 ~120
        ├─ 剔除冒犯性词汇                        剔除 ~15
        ├─ 剔除空释义 / 乱码                     剔除 ~13
        ├─ 释义压缩（每词性 ≤2 义项，≤2 词性，≤48 字符）
        └─ 截取前 8000 条
        ▼
   words.json（8000 条，555 KB）
```

白名单保留的大写词（因为它们是真正的常用词而非专名）：

```
I  OK  TV  Mr  Mrs  Ms  Dr  PC  CEO  DNA  GDP  IQ
```

清洗逻辑见 `scripts/build-data.mjs` 的 `tidyMeaning()` 与 `isAcceptable()`。

## 2. 本地存储 `localStorage['word-memory/v1']`

### 2.1 结构

```json
{
  "v": 1,
  "meta": {
    "createdAt": 1762000000000,
    "updatedAt": 1762086400000,
    "dataVersion": "1.0.0-4afd6304292568dc-8000"
  },
  "settings": {
    "newPerDay": 20,
    "reviewPerDay": 200,
    "levels": [1, 2, 3, 4],
    "order": "frequency",
    "answerMode": "mixed",
    "autoPlay": false,
    "showPhonetic": true,
    "theme": "dark",
    "sessionSize": 20
  },
  "words": {
    "0": { "s": 2, "ef": 2.5, "iv": 3, "reps": 2, "due": 1762260000000,
           "last": 1762000000000, "lapse": 0, "star": 0, "seen": 2, "ok": 2, "step": 0 },
    "5": { "s": 3, "ef": 2.5, "iv": 0, "reps": 0, "due": 0,
           "last": 1762000000000, "lapse": 0, "star": 1, "seen": 0, "ok": 0, "step": 0 }
  },
  "daily": {
    "2026-11-07": { "n": 20, "r": 0, "c": 20, "a": 20, "ms": 240000 }
  }
}
```

### 2.2 字段说明

**`words` 的键**是词库索引（字符串形式），值是 `StudyState`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `s` | 0–3 | 状态：0 新词 / 1 学习中 / 2 复习中 / 3 已掌握 |
| `ef` | 1.3–3.0 | 难度因子 |
| `iv` | 0–365 | 当前间隔（天） |
| `reps` | int | 复习阶段成功次数 |
| `due` | timestamp | 下次到期时间（毫秒） |
| `last` | timestamp | 上次作答时间 |
| `lapse` | int | 遗忘次数 |
| `star` | 0/1 | 重点标记 |
| `seen` | int | 累计作答次数 |
| `ok` | int | 累计答对次数 |
| `step` | 0–2 | 学习步骤索引 |

**`daily` 的键**是本地日期 `YYYY-MM-DD`：

| 字段 | 说明 |
| --- | --- |
| `n` | 当天新学的词数 |
| `r` | 当天复习的词数 |
| `c` | 当天答对（自评 ≥ 记得）的卡片数 |
| `a` | 当天总作答卡片数 |
| `ms` | 当天累计作答耗时（毫秒，单卡上限 5 分钟） |

### 2.3 只存变化

满足以下条件的词**不会**写入 `words`（等于使用默认状态）：

```js
s === 0 && star === 0 && seen === 0 && lapse === 0
```

所以新用户首次打开时 `words` 是 `{}`。这是「默认状态不落盘」策略，也是 8000 词全学完后体积仍能控制在 1 MB 以内的原因。

### 2.4 写入时机

| 触发 | 行为 |
| --- | --- |
| 任何状态变更 | 标记 dirty，400 ms 防抖后写入 |
| `visibilitychange → hidden` | 立即 flush |
| `beforeunload` | 立即 flush |
| 导出 / 结束会话 | 立即 flush |

写入失败（配额耗尽 / 隐私模式）不会抛异常，而是设置 `store.lastError` 并保持内存态继续工作。

## 3. 导出备份

`store.export()` 输出格式与 localStorage 结构基本一致，额外包含 `meta.exportedAt`：

```json
{
  "v": 1,
  "meta": { "createdAt": …, "updatedAt": …, "dataVersion": "…", "exportedAt": 1762086400000 },
  "settings": { … },
  "words": { … },
  "daily": { … }
}
```

相比 localStorage 原样序列化，导出时做了 `JSON.stringify(obj, null, 2)` 缩进，便于人工查看与 diff。

### 导入校验

```js
importJSON(text) {
  1. JSON.parse 失败          → { ok: false, error: 'JSON 解析失败：…' }
  2. 不是对象 / 缺少 words     → { ok: false, error: '文件内容不是有效的备份…' }
  3. migrate() 清洗每条记录    → 非法条目被丢弃，合法条目保留
  4. 替换内存数据并立即保存    → { ok: true, count: N }
}
```

导入失败时**不会**破坏现有数据——只有 `migrate` 成功后才赋值。

## 4. 版本与迁移

`SCHEMA_VERSION = 1`。当前只有 `migrate()` 一条路径，负责：

1. 补齐缺失字段（用 `normalizeState`）
2. 丢弃非法键（非数字索引）
3. 修正越界值（EF、间隔、时间戳）
4. 丢弃默认状态记录（压缩体积）
5. 清洗 `daily`（只保留 `YYYY-MM-DD` 键）

### 未来加字段的做法

```js
export const SCHEMA_VERSION = 2;

function migrate(parsed) {
  const out = migrateV1(parsed);          // 先升级到 v1 结构
  if ((parsed.v || 1) < 2) {
    // v1 → v2 的转换逻辑
    out.settings.someNewField = defaultValue;
  }
  out.v = SCHEMA_VERSION;
  return out;
}
```

原则：**只加字段，不改语义**。字段改名要写双向映射，否则用户回退版本会读到脏数据。

### 词库版本校验

`meta.dataVersion` 形如 `1.0.0-4afd6304292568dc-8000`（词库版本 - 源数据指纹 - 词数）。

如果用户导入的备份来自不同词库版本，索引可能错位。当前实现是：

- 启动时若本地 `dataVersion` 为空则写入当前值
- 不匹配时暂不阻断（避免误伤），但 `docs` 与设置页会展示版本信息供排查

后续如需严格校验，可在 `createApp` 中比较并提示用户。
